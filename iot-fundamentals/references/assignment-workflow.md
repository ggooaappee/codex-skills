# 物联网课程作业工作流

## 1. 拆解题目

先把作业要求写成可核对的表：

| 项目 | 要回答的问题 |
| --- | --- |
| 输入 | 需要读取哪个传感器或按键？ |
| 处理 | 阈值、比较、映射、滤波或状态切换是什么？ |
| 输出 | LED、RGB、OLED、蜂鸣器、电机、舵机或通信？ |
| 时序 | 是否需要延时、闪烁次数、采样周期或连续旋转？ |
| 约束 | 指定引脚、指定函数、必须使用某个库？ |

如果作业没有给出阈值，使用课件原值，并在交付说明中列为可调参数。

## 2. 匹配代码库

1. 在 `assets/code-library/patterns/index.md` 找到对应课程。
2. 读取模块模式文件。
3. 检查 `pin-map.md` 中的共享引脚和冲突。
4. 如果有组合需求，先读取 `integration-recipes.md`，再修改而不是拼接多个完整 `setup()/loop()`。
5. 可用 `scripts/find_pattern.py` 检索关键词。

## 3. 设计单文件程序

优先使用一份可提交的 `.ino`，结构如下：

```cpp
// 1. 第三方库和课程库
#include <OLED.h>

// 2. 引脚和阈值
#define LED 3

// 3. 全局对象和状态
OLED myOLED;

// 4. 自定义辅助函数

void setup() {
  // 所有模块初始化
}

void loop() {
  // 先读取，再处理，再输出
}
```

要求：

- 不复制多个 `setup()` 或 `loop()`。
- 不改变用户指定的模块和引脚。
- 优先沿用课件的 API、函数名和阈值。
- 修复明显语法错误和弯引号，但不悄悄改掉课件算法。
- 组合按键、传感器和电机时，检查是否被长时间 `delay()` 阻塞。
- 若多个模块共用同一引脚，先提出换脚、分时使用或按实际硬件重新分配，不能假装可以同时工作。

## 4. 验证

至少执行以下检查：

1. 每个使用到的库都有 `#include`。
2. 只有一个 `setup()` 和一个 `loop()`。
3. 所有花括号、圆括号和方括号配对。
4. 引脚值不违反 `pin-map.md` 的冲突规则。
5. 传感器返回单位和阈值一致。
6. 低电平按键使用 `LOW`。
7. LED、RGB、蜂鸣器和 OLED 输出位置符合题目。
8. 多步骤动作有必要的延时，并能返回初始状态。

运行：

```bash
python scripts/validate_sketch.py path/to/assignment.ino
```

如果 Arduino CLI、开发板核心和课程库可用，再实际编译。没有工具链时必须明确说明只做了静态检查。

## 5. 交付结构

建议生成：

```text
作业名称/
├── 作业名称.ino
├── README.md
└── 接线说明.md
```

`README.md` 要说明：

- 实现了哪些题目功能
- 使用了哪些模块和库
- 阈值和可调参数
- 烧录与测试方法
- 尚未验证的风险

`接线说明.md` 只写实际使用的引脚和模块，不要复制整张课件引脚表。

## 6. GitHub 发布

只有用户明确要求上传时才执行。读取 `github-publishing.md`，不要上传课件原件、账号密钥、学号姓名或未获授权的版权材料。
